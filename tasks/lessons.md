# Collaboration lessons

- Keep the initial planning scaffold limited to artifacts the team expects to use. For Happy Path, start with the PRD, individual idea notes, and parallel task files; add separate milestone or hackathon-planning documents only when requested.
- Use **Happy Path** as the canonical core-product name. Reserve **Detour** for the planning extension, and use lowercase “detour” for the generic routing concept.
- Keep one canonical PRD. Fold build constraints and acceptance criteria into it, and create a separate implementation plan only when the team explicitly needs one.
- Treat Quick Picks and natural-language requests as synchronized editors for one Trip Brief. Explicit current-trip input outranks saved or inferred preferences.
- Keep the default map centered on one Happy Path: use ambient layers for continuous conditions, icons for discrete route-relevant assets, and move secondary or colliding evidence into toggles or explanations.
